A. Arrival

Runs before the visitor reaches the screen

  1. A1The camera outside the door sends frames to Arrival ingest. It only logs. Nobody is greeted.
  2. A2Ingest samples frames and counts each person once per visit.
  3. A3Face matching compares against pgvector. Known people are logged as arrivals.
  4. A4Unknown faces go to the web search job, once per person per visit, with a daily cap.
  5. A5FaceCheck.ID returns the top 3 candidates.
  6. A6The photo and matches are saved with a 90-day expiry date.

B. At Screen 2

Recognition, confirmation, voice and booking

  1. B1Camera 2 scans the visitor. A known face is greeted by name.
  2. B2An unknown face is linked to its entrance capture, so the ready top 3 photos appear as Is this you?
  3. B3The visitor's pick, or a new entry, is saved as Pending.
  4. B4The browser opens the voice session with OpenAI Realtime using a short-lived token from our backend.
  5. B5The assistant calls Voice tools to look up, register and book.
  6. B6Podcast and TikTok room bookings go to Spacebring.
  7. B7Meeting room bookings stay in our database.
  8. B8Registration and link results are stored in PostgreSQL.

C. Approval

Nothing is confirmed without an admin

  1. C1Admin opens the approval queue in the admin panel.
  2. C2Approving turns a Pending record into a confirmed visitor. Approval rules are still to be defined.

The two PostgreSQL boxes are one database. One holds face vectors, the other holds everything else. Each record carries a 90-day expiry date; automatic deletion stays off for the POC. Qdrant is retired once pgvector is in place.
